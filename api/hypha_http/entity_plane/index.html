Module entity_plane

Expand description

The kind-plane port + registry — how /api/entities* serves multiple entity kinds through one substrate surface (the ADR-0091 contract, landed in peregrin as PL-004). Each resident entity kind registers one EntityPlane impl that owns its slice of the surface: entity docs, its <ns>.<verb> op table, and snapshot export/import. The substrate routes parse just enough to pick a plane (body.kind, the op namespace) and hand over verbatim — payloads stay opaque and no global verb table grows here.

Integrations register their planes at composition via crate::HyphaState::with_kind / state.kinds.register(...). A sepia-session plane lives in peregrin and plugs in there — this crate names no session type.

Structs§

EntityContext
The substrate-owned context every EntityPlane method receives — the kind registry plus the host’s opaque state payload. This is the seam the entity surface is extractable along: it names no session, orchestration, or store type. A host stuffs its state (e.g. Arc<HyphaState>) in as host; planes that wrap host handlers downcast it back (ctx.host::<HyphaState>()), while kind-agnostic planes only need Self::kinds.
KindRegistry
kind → EntityPlane registry carried on crate::HyphaState::kinds. Registration order matters for two fallbacks: the first registered plane is the default for un-namespaced ops and for creates/imports that omit kind.

EntityPlane
One registered entity kind’s serving plane. Responses are the kind’s own wire surface under /api/entities* — the substrate forwards them untouched, so an impl controls its status codes, error shapes, and payload translation entirely.
