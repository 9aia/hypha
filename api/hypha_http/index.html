hypha-http — the axum driving adapter for the hypha entity substrate. Serves the kind-agnostic /api/* surface: entity planes (/api/entities*), the node event feed (/api/events), node identity, pairing + bearer auth, directory/user info, and web push subscriptions. Integrations (peregrin’s session plane, future campaign planes) compose app with their own routes and register EntityPlanes through HyphaState::with_kind; the EntityContext::host downcast is how planes reach host state.

Modules§

auth
Bearer auth — port of peregrin’s app.ts isAuthorized/ unauthorizedResponse plus the login/logout cookie exchange and POST /api/pair code redemption. Substrate routes only: the per-session SSE ?access_token path is the integration’s to add (see [is_query_token_path]).
entity_plane
The kind-plane port + registry — how /api/entities* serves multiple entity kinds through one substrate surface (the ADR-0091 contract, landed in peregrin as PL-004). Each resident entity kind registers one EntityPlane impl that owns its slice of the surface: entity docs, its <ns>.<verb> op table, and snapshot export/import. The substrate routes parse just enough to pick a plane (body.kind, the op namespace) and hand over verbatim — payloads stay opaque and no global verb table grows here.
env
Boot-time configuration — the substrate half of peregrin’s env.ts: bind, auth token, CORS, SSE keep-alive, pairing, node identity, and the push document. Session-plane tunables and integration-specific knobs deliberately don’t ride Env — each integration parses its own. Env::parse fails fast on bad values.
feed
The substrate event feed behind GET /api/events — a process-wide tokio::sync::broadcast of kind-tagged payloads that integrations emit into and SSE connections drain. The shape is deliberately generic (kind: &'static str + opaque serde_json payload): producers name their own event kinds (session, meta, campaign, …) and consumers branch on the SSE event: field. Integrations bridge their domain events in — e.g. peregrin maps session-plane events onto this feed.
node
Stable per-machine node identity — port of apps/server/src/node.ts. The id is minted on first boot and persisted to $HYPHA_HOME/node.json; afterwards it is read back, never regenerated.
pair
Pairing — port of apps/server/src/pair.ts: the one-time short code hypha pair writes to $HYPHA_HOME/pair-code redeems for a long-lived hypha_… bearer credential. Issued credentials persist as sha256 hashes in $HYPHA_HOME/tokens.json — the file alone can’t authenticate.
ratelimit
In-memory per-IP sliding-window rate limiting — guards the credential-bootstrapping POST /api/pair (the one route that mints a bearer token without prior auth) against online code guessing. No deps: a bounded HashMap<IpAddr, …> of attempt timestamps.
routes
Route helpers — the substrate half of peregrin’s routes/shared.ts: the {error} body shape, JSON-body reading with per-route caps, and query-param decoding. Session-shaped wire types and the ControlError → status mapping stay with the integration that owns them.

Structs§

HyphaState
Shared state threaded through every substrate handler — the createApp options object minus everything an integration owns (session planes, meta stores, campaign state). Clone is cheap (Arc/Mutex/registry clones) because axum clones state per request.

Functions§

app
The standalone substrate router — app_routes plus the 404 fallback and the state applied. Integrations composing several routers under one listener use app_routes instead and install their own single fallback.
app_routes
Build the substrate route table + middleware WITHOUT the terminal fallback — returns Router<HyphaState> so an integration can .with_state(...) it and merge it with its own router under one listener. axum panics merging two routers that both carry a custom fallback, so the composer installs exactly one (see app_routes vs app).
serve
Bind env.host:env.port and serve the app. The bind guard already ran in Env::parse; callers wanting graceful shutdown own the listener themselves.
