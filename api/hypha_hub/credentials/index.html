Module credentials 

Source
Expand description

Where the hub keeps node bearer tokens between restarts.

HYPHA_NODES @token / HYPHA_NODE_TOKEN are explicit config and always win; an env token also seeds an empty store slot at boot — the migration path off plaintext env (drop @token after one boot, the token keeps working from the store). A stored credential is never overwritten by env config; rotation goes through re-pairing. Nodes listed without a token — and credentials minted by the pair flow — resolve and persist through a NodeCredentials store: the OS keyring (Secret Service on Linux/*BSD, Keychain on macOS, Credential Manager on Windows) when reachable, else credentials.json (0600) under the hub home — the documented headless path. HYPHA_CREDENTIAL_STORE=auto|keyring|file picks the backend; auto (default) probes the keyring once at boot.

Keyring ops are blocking (a dbus round-trip on Linux) — async callers go through tokio::task::spawn_blocking, same as ureq.
