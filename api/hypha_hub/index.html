Crate hypha_hub 

Source
Expand description

hypha-hub — the node-API gateway. Bridges client traffic to the node daemons and runs the multi-node sync engine:

  • /api/events — SSE bridge to HYPHA_NODE_URL (EventSource can’t carry cross-origin auth cleanly; proxying keeps the client same-origin).
  • /api/entities/{id}/stream — per-entity live stream, routed to the owning node and shaped by the kind’s hypha_sync::KindPolicy::stream_path.
  • /api/push/* — the hub-owned push subscription store (one subscription fans out to every paired node).
  • /api/* — generic passthrough for the rest of the node API, entity-scoped calls routed to the owning node on multi-node setups (HYPHA_NODES).

sync_api::SyncEntityApi is the hub’s EntityApi: entity lists read the merged projection and writes queue in the durable outbox when a node is down.

The hub is policy-injected: kind_policies::default_kind_policies is an empty registry — integrations (peregrin’s session plane, campaign planes, …) supply their hypha_sync::KindPolicies via hub_state_with/[hub_state_from_with]. A bare hub still gateways the whole substrate contract.

Modules§

auth
Client → hub auth — the hub’s own token surface. Node bearer tokens stay server-side (HYPHA_NODES / HYPHA_NODE_TOKEN); this gate covers everything the hub itself serves.
credentials
Where the hub keeps node bearer tokens between restarts.
entity_routes
The substrate’s HTTP entity surface — /api/entities* on the hub. Reads hit the merged projection (every paired node), ops go through SyncEntityApi::submit_op so they queue in the durable outbox when the owning node is down, and snapshots route to the owning/target node. These handlers are registered ahead of the /api/{*rest} passthrough so the merged surface wins.
kind_policies
The hub’s entity-kind policy registry — the injection seam for integrations.
proxy
Hub → node HTTP bridges.
push_routes
Hub-owned push subscriptions — one subscription store for every node, so a browser subscribes once and gets notified by all of them. runFinished/permissionRequested feed markers (emitted by each node’s live listener) drive the fan-out.
sync_api
SyncEntityApi — the hub’s EntityApi backed by hypha-sync: the entity list reads the local projection (merged across every paired node), detail + detail-stream traffic proxies to the owning node live, and ops go through SyncEngine::submit_op so they queue in the durable outbox when the node is down.

Functions§

hub_state
HubState for a running hub: the sync engine + [SyncEntityApi]. HYPHA_NODES (id=url[@token];…) wins; HYPHA_NODE_URL/HYPHA_NODE_TOKEN is the single-node shorthand. Nodes listed without a token resolve one from the credentials store (OS keyring → file fallback — that store is also where the pair flow persists minted tokens), and an env-provided token seeds an empty store slot so the plaintext can leave the env. The projection + outbox live under $HYPHA_HOME/hub/ so they survive restarts.
hub_state_with
hub_state with an integration-supplied kind-policy registry — the P4 composition seam. The same registry feeds the sync engine (diff projection, op params), the feed hook (push rules), and the entity API (gating, creates, actors, stream paths).
router
Build the axum router. HubConfig → HubState happens in hub_state; tests construct HubState directly with a stub EntityApi.
