Module sync_api 

Source
Expand description

SyncEntityApi — the hub’s EntityApi backed by hypha-sync: the entity list reads the local projection (merged across every paired node), detail + detail-stream traffic proxies to the owning node live, and ops go through SyncEngine::submit_op so they queue in the durable outbox when the node is down.

Kind-specific behavior — op gating (sepia.* vs *.meta*), create validation ("session" alias), outbox op classification, external lock holders (indexDoc.lockHolderPid), and push rules — resolves through the KindPolicies registry (crate::kind_policies); this file names no kind itself. When the integration-backed /api/entities surface lands (PL-004 phase 4), the registrations move with their integrations.

resolve_node_tokens
Boot-time token resolution — the crate::credentials doc has the model. An env @token/HYPHA_NODE_TOKEN is explicit config: it wins for this boot and seeds the store when the node has no stored credential yet — the migration path that lets the plaintext leave the env (drop @token after one boot; the token keeps working from the store). A stored credential is never overwritten by env — rotation goes through re-pairing (adopt_credential writes the minted token through). Tokenless nodes resolve a stored credential into node.token.
