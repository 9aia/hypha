Getting started ​

Hypha is the distributed substrate extracted from peregrin's entity plane (org plan PL-005, ADR-0001). It ships two binaries: hypha (the node host, hypha serve) and hypha-hub (the multi-node gateway). A bare node mounts zero entity kinds — integrations register theirs at composition.

Build from source ​

bash
git clone git@github.com:9aia/hypha.git
cd hypha
./scripts/setup.sh      # wires git hooks
cargo xtask check       # fmt + clippy -D warnings
cargo xtask test        # whole suite (nextest if present)

Rust 1.98 (see rust-toolchain.toml), edition 2024.

Install the binaries ​

There is no xtask install — install straight from the workspace:

bash
cargo install --path crates/hypha-node --locked   # → ~/.cargo/bin/hypha
cargo install --path crates/hypha-hub --locked   # → ~/.cargo/bin/hypha-hub

Smoke run ​

A bare node needs no kinds and no config — loopback binds may go tokenless:

bash
hypha serve            # HYPHA_HOST/HYPHA_PORT, default 127.0.0.1:18787
curl localhost:18787/api/health        # {"ok":true}
curl localhost:18787/api/node          # node descriptor
curl localhost:18787/api/entities      # {"entities":[]} — no kinds yet

The hub gateways that node (HYPHA_NODE_URL defaults to http://127.0.0.1:18787):

bash
hypha-hub              # HYPHA_HUB_HOST/HYPHA_HUB_PORT, default 127.0.0.1:13000
curl localhost:13000/api/entity-index  # merged index (one row)
curl localhost:13000/api/pending-ops   # outbox depth

See Environment for the full HYPHA_* surface and Wire API for the routes.

Upgrading from peregrin — secrets move ​

hypha-keyring stores under the secret-tool service attribute "hypha" (was "peregrin"), and hypha-hub node credentials live under "hypha-hub" (was "peregrin-hub"). There is no automatic migration — old entries are orphaned, not moved. After upgrading:

  • re-run pairing (POST /api/pair flow) or re-store secrets with secret-tool store --label "hypha: <name>" service hypha name <name>
  • hub node tokens: either re-pair each node, or let an env HYPHA_NODES @token/HYPHA_NODE_TOKEN re-seed the store on the next boot (HYPHA_CREDENTIAL_STORE picks keyring vs file backend)
